2. Dynamic library use
----------------------

The macOS version of SimpleOB uses Qt through dynamically linked
frameworks and PySide6/Shiboken6 runtime libraries.

The distributed Qt frameworks include:

- QtCore
- QtDBus
- QtGui
- QtNetwork
- QtSvg
- QtWidgets

These libraries are separate files inside the SimpleOB application
bundle.

3. Replacing LGPL-covered libraries
-----------------------------------

Users may replace LGPL-covered Qt, PySide6 or Shiboken6 libraries with
compatible modified versions of those libraries for their own use, as
permitted by the LGPLv3.

On macOS, changing or replacing a library inside an application bundle
invalidates the existing code signature of the affected component and
normally also the signature of the application bundle.

SimpleOB does not require a Developer ID signature from the user in
order to use a modified LGPL-covered library.

After replacing an LGPL-covered component, the modified component and
the application bundle can be signed locally using Apple's codesign
tool with an ad-hoc signature.

For example, for a replaced Qt framework:

    codesign --force --sign - <path-to-Qt-framework>

The application bundle can subsequently be re-signed locally:

    codesign --force --deep --sign - <path-to-SimpleOB.app>

The resulting signature can be checked with:

    codesign --verify --deep --strict --verbose=2 <path-to-SimpleOB.app>

An ad-hoc signature does not require an Apple Developer ID certificate.

Depending on the macOS security configuration and how the application
was obtained, macOS may require the user to explicitly approve opening
the modified application.

It is not necessary to disable Gatekeeper globally.
